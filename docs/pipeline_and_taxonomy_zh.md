# 从生成到反馈的 ORSMT 工作流

## 整体分工

LLM 根据自然语言需求生成数学模型和求解器代码。系统分别读取数学模型、捕获代码
实际建立的模型和返回结果，再执行 SMT 检查、错误定位、修复与复核。需要回到
原题判断建模意图时，由 LLM 消费具体反例并提出修改。代码修复在选定数学模型后
通过确定性生成完成，返回结果可以重新求解得到。

数学模型与程序模型必须有独立来源，不能把程序反向读出的模型同时作为书面模型，
否则两者一致只是同源重述。SMT 反馈提供具体的矛盾点，LLM 负责结合原题判断
该改哪一边。两份形式模型一致不自动证明它们同时正确理解了自然语言；有独立
正式参考时，才能再验证它们与该参考的关系。

## Translator

| 输入 | 处理方式 | 转译记录 |
|---|---|---|
| 已有类型化 MILP 对象 | 直接进入统一中间表示 | 形式模型指纹 |
| 字典、JSON、Markdown 中完整 JSON 代码块 | 确定性解析 | 原始文本、输入哈希、模型指纹 |
| LP、MPS 文本或文件 | 官方求解器文件读取器再提取 MILP | 同时记录原文件与原生数值表示 |
| 已实例化 Gurobi 模型对象 | 读取变量、线性约束、目标和变量域 | 模型指纹、转译方式 |
| 自由 LaTeX、文字建模说明 | 显式 LLM 转译回调 | 原文、转译者、假设、调用成本；保留“候选解释”标记 |
| 求解器 Python 代码 | 由宿主隔离执行并捕获实际模型 | 不用 LLM 代替程序执行 |
| 其他建模系统 | 注册宿主 adapter | 不假定尚未实现的原生支持 |

统一中间表示是内部接口，不要求外部方法只输出 JSON。LaTeX 的 LLM 转译与
需求驱动的修复是两个动作：转译时只保留原数学模型，不能偷偷纠正其中的错误。
当前不声称任意 LaTeX 都能机械化解析。LP/MPS 遵循文件格式本身的含义；LP
表达式不能任意采用普通数学排版，例如裸常数可能被读成变量，需要明确的合法
编码。带目标常数时优先使用 MPS 或原生模型对象保留常数。

官方格式说明：https://docs.gurobi.com/projects/optimizer/en/current/reference/fileformats/modelformats.html

## 检查与 taxonomy

| 层次 | 发现的问题或性质 | 证据 |
|---|---|---|
| 变量 | 整数性、二元域、上下界不一致 | 已复核的可行域区分点违反另一模型的变量域 |
| 约束 | 约束缺失或放松所表现的可行域扩大 | 程序允许、书面模型不允许的具体点 |
| 约束 | 额外或过紧约束所表现的可行域缩小 | 书面模型允许、程序不允许的具体点 |
| 目标 | 偏好排序不一致 | 两个共同可行点在两个目标下的排序不同 |
| 目标 | 数值不一致 | 同一决策对应不同目标值 |
| 结果 | 解不可行、报告值错误、存在更好解 | 可行性、目标回代、最优性查询 |
| 规范化问题 | 单个冗余约束 | 删除该行后，其余约束仍蕴含该行 |

可行域扩大或缩小是相对于被比较的书面模型而言，不能据此自动断言代码错误。
系数、关系号、右端项、变量类型、目标方向等结构差异另行保留为定位线索，不把
改写形式差异直接计为语义错误。冗余约束必须进入问题统计和规范化处理，
同时分列其与可行域变化的区别。冗余比例、实际删行比例和剩余无冗余的认证比例均报告。

逐行检查给出书面约束被程序保持的比例、程序约束由书面模型蕴含的比例和双方
各自的冗余约束比例。未判定行留在完整分母中，决策覆盖率另报。不同公式拆分会
改变行数，因此逐行比例需要同时给出计数和编码口径；模型级可行域一致性用于
比较整体语义。多个单独冗余的约束不一定可以同时删除。

## 统一 feedback

反馈对象使用稳定 schema，包含案例标识、关系判定、错误类型、涉及的变量或
约束、反例赋值、结构差异、修复对象及其依据，以及转译记录。它有两种直接用法：
离线汇总各模型和 benchmark 的错误谱；作为外部 autoformulation 方法的修复
输入。修复之后重新执行和验证，记录哪些关系被修复以及是否引入新的不一致。

`ORSMTWorkflow.check` 输出完整诊断，`ORSMTWorkflow.repair` 接受宿主执行器
和修复回调。修复提示中已加入 `orsmt-feedback-v1`，不要求外部方法换掉自己的
生成器。修复 LLM 可返回 JSON 数学模型或声明格式的 LP/MPS；不会隐含增加一次
自由文本转译 LLM 调用。其他转译调用成本单独记录。

## 本轮验证范围

使用真实 NL4Opt-67 候选进行 JSON、LP、MPS 和原生 Gurobi 模型的格式回归，
比较转译后的模型语义与发现的不一致类型。LP/MPS 由保留的真实数学模型导出，
不是声称原 LLM 已自然生成这些格式。自由 LaTeX 回调目前用单元测试验证接口，
尚未形成真实大模型转译准确率结果。没有据此生成或替换论文实验数据。

本文件为项目使用与接口说明，不直接放入论文正文或附录。

### 已完成的真实候选检查

NL4Opt-67 的四种格式转译后模型指纹相同，全部格式等价性检查通过。四条书面
约束中三条被实际程序保持，一条不被保持；反方向的四条程序约束全部由书面模型
蕴含。双方各有两条逐行检查下的冗余约束。这里“不被保持”表示两份形式对象的
差异，不是自动认定程序错误；该案例此前依据原题复核，修复的是书面模型。
这些是单个真实候选的接口回归结果，不是全量实验比例。
