# MILP 修复流程与当前实现

## 修什么、谁来决定

输入包含原题、LLM 给出的结构化数学模型、求解器代码。代码实际建立的 MILP
由求解器接口捕获，返回解和目标值来自原生执行。SMT 检查的是这些形式对象的
关系，而不是用另一个 LLM 给它们打分。

| 情况 | 修改对象 | 当前实现 |
|---|---|---|
| 指定数学模型为规范，代码与它不一致 | 代码 | 从数学模型确定性生成固定实例的 Gurobi 程序 |
| 完整正式参考与代码一致，但与数学模型不一致 | 数学模型 | 用参考修正模型，原代码不变 |
| 完整正式参考与两个候选都不一致 | 数学模型和代码 | 修正数学模型，再机械化生成代码 |
| 没有正式参考，两个候选不一致 | 由源文本判断修改对象 | LLM 引用原题、提出修复对象和模型；随后实际执行并由 SMT 检查 |
| 模型和代码一致，但解、目标值或最优性不成立 | 返回结果 | 重新求解同一个捕获模型，检查新结果，不改原程序 |

代码生成是完整实例程序的重建，不是任意 Python 文件的局部补丁。结果修复返回
新的解和目标值，尚不改写原程序中的结果打印或后处理语句。

## 每次修复后的检查

完整模型比较包括两个方向的可行域包含、目标偏好一致性和目标数值一致性。
例如两个目标相差一个正常数倍，它们可能选出相同最优解，但不能直接按相同金额
报告。本轮把数值一致性独立接入修复检查。单独的检查接口支持显式仿射单位换算；
当前批量修复按同一单位比较，不自动拟合换算关系。

结果检查包括解的可行性、报告值是否等于目标函数代入值、是否存在更好的可行解。
修改后的程序必须重新执行、重新捕获，不能用 LLM 声称的模型代替实际建立的模型。
被选定保留的数学模型或代码保持不变。若提供正式参考，修复前后使用同一份参考。

LLM 的输入包括原题、当前两个候选和 SMT 证据，不包括 benchmark 的标准最优值。
LLM 返回案例 ID、修改对象、原题中的完整引文、修改理由，以及需要修改时的完整
线性数学模型。它不负责发出验证结论。正式参考也不能由 LLM 的自述自动建立。

## 真实案例：NL4Opt-67

这是原 benchmark 中 32B 候选的真实案例。原题要求旧运输公司的出车次数至少占
全部出车次数的 40%。记新公司的次数为 n、旧公司的次数为 o。

| 内容 | 原候选或验证结果 |
|---|---|
| 原题关键句 | “at least 40% of all trips must be made by the old company” |
| 候选数学模型中的比例约束 | o − n ≥ 0.4 |
| 实际代码中的比例约束 | o ≥ 0.4(n + o) |
| 根据原题复核的约束 | 3o − 2n ≥ 0 |
| 区分两个候选的点 | n = 15，o = 10；代码允许，原数学模型不允许 |
| 本次参考辅助修复 | 只修正数学模型，原求解器代码保持不变 |
| 原生执行结果 | n = 2，o = 13，柴油用量 580 |
| 修复后 | 模型与代码一致，返回解和目标值验证通过 |

本次集成检查使用人工复核的完整参考模型，未调用 LLM，不能计为 LLM 自动修复实验。
最优值在修复前后仍为 580，说明最优值是否变化不能替代模型语义修复的检查。
另一个测试分支明确把原数学模型指定为规范，机械化代码生成也能使两个形式对象
一致；它证明的是代码生成能力，而不是原数学模型符合自然语言需求。

## 全量对照

当前 MILP 范围为 12 个来源、3,034 道题、七个 Qwen2.5 检查点，共 21,238 个
分配输出。OPT-Engine 不在范围内。原题与候选保持相同 ID，错误和未完成案例保留
在总分母中。计划不引入重复随机种子；LLM 温度为零，每例修复调用预算显式固定。

第一组指定原数学模型为规范，使用机械化代码修复；第二组由 LLM 根据原题和
反例选择修改对象，再进行机械化实现和 SMT 再验证。这两组用于回答是否应先
识别错误发生在哪个候选中，不是同一 LLM 预算的提示词消融。

运行器记录修复接受数、原始不一致数、按修改对象分组的结果、LLM 调用数和成本。
这些统计表示验证和修复过程，不能直接称为 benchmark 正确率。标准答案一致率、
错误变正确、正确变错误需要在修复结束后独立评估；标准答案不进入修复提示。
当前未产出本版全量 LLM 修复效果表，也未据此更新论文实验数字。

## 程序入口

- `orsmt.repair_workflow`：比较模型、选择修复对象、复核修改。
- `orsmt.repair_engine`：执行修复循环，连接原生求解器与 LLM 回调。
- `orsmt.milp_codegen`：确定性 MILP 代码生成。
- `ops/check_repair_integration.py`：真实案例端到端检查。
- `ops/run_routed_milp_repair.py`：全范围运行及断点结果检查，`--plan` 只生成计划。

这份文件是项目实现说明，不作为论文正文或附录内容。
